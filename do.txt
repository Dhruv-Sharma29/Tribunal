DONE — the rich progress renderer (Phase 4)
--------------------------------------------
  - progress.py           ProgressRenderer: a TraceWriter SUBSCRIBER, not a second code
                          path. -q removes it and the recorded run is identical.
  - orchestrator.py       `subscribers=[...]`, attached to the writer at run start
  - cli.py                --quiet / -q
  - tests/test_progress.py  18 tests, every one driven by a real run

Two outputs from one state machine: a rich.Live on a terminal, one line per step when
redirected (chosen on console.is_terminal, not on a flag). Both critics render on ONE
line with a "parallel" marker -- that is the concurrency claim, made visible for free.

Two bugs worth remembering (docs/13 §§ 42-43):
  * a state event's `round` is the round IN PROGRESS, not the one being entered, and the
    Coder's llm_response arrives BEFORE its PROPOSE state. Rows are built from content
    events, never from state transitions.
  * a printed line cannot be taken back: flushing per event made `grounding` print after
    its first tool and `critique` print after its first critic -- losing the second one,
    on the line whose entire job is showing two at once.

[x] DONE: scripts/check-exit-codes.sh -- 15 checks, offline, and it HAS been run.
      Writing it found two real things (docs/13 §§55-56):
      * exit codes 3 (FAILED) and 4 (BUDGET_EXHAUSTED) were UNREACHABLE. Both
        input_unusable and budget_exhausted are Decision.ESCALATE, and the exit code was
        derived from the Decision alone. A pipeline keyed on 4 to page about cost would
        never have fired. Fixed via Report.terminal_state (TerminalState was declared in
        contracts and used nowhere -- a third dead definition, same family as §§44-45)
        and an ordered exit_code_for().
      * `replay` exited 0 on a failed run, so the contract could only be tested by
        spending money. replay now exits with the outcome of the run it reports, which
        is right anyway and makes the matrix checkable from 5 committed trace fixtures
        (tests/fixtures/traces/).
      docs/08's `5` for usage resolved in favour of the code's `64` (EX_USAGE); a sixth
      outcome would have collided with 5.
